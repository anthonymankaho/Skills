# Skill: Systematic Debugging (Superpowers)

Use for any bug, test failure, or unexpected behavior, before proposing a fix. Iron law: **no fixes without root-cause investigation first**. Four phases — (1) root-cause investigation (read errors fully, reproduce reliably, check recent changes, trace data flow), (2) pattern analysis against working examples, (3) single hypothesis + minimal test, (4) implementation with a failing test created first (hands off to [[Skill - Test-Driven Development|test-driven-development]]). After 3+ failed fix attempts, stop and question the architecture instead of trying a 4th patch.
